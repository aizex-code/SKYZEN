SKYZEN — VERIFIED FIX HISTORY
Purpose: cumulative fix record. Separate attempted/automated-verified changes from user-confirmed GUI behavior. Carry this file forward with each release.

PATCH 01 — STABILITY BASELINE
Recorded changes from prior patch notes:
- Guarded body clicks/tiny movement so move mode does not enter trim-only math.
- Normalized waveform path handling.
- Added long clip-label elision and hid duration text on narrow clips.
Automated tests were reported as passing in that patch.
GUI verification: not recorded.

PATCH 02 — TRIM INTERACTION FIX
Attempted changes:
- Used stable global pointer coordinates for trim delta calculation.
- Separated left/right trim hit zones on narrow clips.
- Added tests for pointer-delta conversion.
Automated verification: 110 passed, 3 skipped; compilation passed in Patch 02.
User feedback: left trim followed by right trim could collapse a clip to a very small segment. Therefore Patch 02 trimming is NOT confirmed and its behavior is superseded by Patch 03.

PATCH 03 — SEQUENTIAL TRIM SOURCE-RANGE FIX
Attempted changes:
- Added a safe source-length resolver based on source-in plus visible duration when source-duration metadata is absent/stale.
- Probe media duration when possible at trim start and cache the bound for the active drag.
- Added regression tests for left-trim then right-trim behavior under missing/stale metadata.
Automated verification: 112 passed, 3 skipped; Python compilation passed.
GUI verification: PENDING USER CONFIRMATION.

CONFIRMATION CHECKLIST
[ ] Left trim follows the pointer without jumping or accelerating.
[ ] Right trim shortens and extends correctly within the real source-media range.
[ ] Left trim followed by right trim preserves the clip and does not collapse it.
[ ] Right trim followed by left trim behaves correctly.
[ ] Both trim directions remain frame-accurate at different zoom levels.
[ ] A clip cannot become shorter than one frame.
[ ] Narrow clips allow both edges to be selected.
[ ] Move, split, playback, undo/redo, and save/reopen still work after trimming.

Only check an item after live GUI testing or a repeatable integration test proves it.


PATCH 04 — FRAME-STABLE TRIMMING AND PREVIEW REFRESH
Attempted/implemented changes:
- Freeze pixels-per-frame and source_in at mouse-down; derive all mouseMove updates from that original state to avoid accumulating the left-trim delta.
- Remove the main-clip frame-zero override that could desynchronize start, duration and source_in during a left trim. The main track row itself is not moved.
- Publish the updated active timeline stack on trim release so the preview controller invalidates the previous project snapshot and renders the current trim.
- Add regression tests for left/right restoration, known source bounds, preview input trim values, snapshot signature changes, and trim-release synchronization.
Automated verification: full suite 119 passed, 3 skipped; compileall passed.
GUI verification: PENDING USER CONFIRMATION. PySide6 GUI was not launched in this environment.

PATCH 05 — AUDIO DROP STABILITY AND TRACK ORDER
Implemented (GUI verification pending):
- Canonicalized Audio/Image/Video kind strings at the model boundary.
- Added audio-specific insertion gaps below Main; audio is no longer accepted by visual overlay gaps.
- Corrected audio insertion index to use the audio stack only.
- Added sticky first-audio-lane geometry beneath Main, reserving viewport space for both rows.
- Bounded/tiled audio waveform drawing to avoid full-clip-width pixmap allocation.
- Added drop failure logging and regression tests for shared audio row geometry.
Automated verification: 91 tests passed, 3 skipped; Python compileall passed.
GUI verification: PENDING. The user reported the app closes when music is dragged to the timeline; this patch is not marked confirmed until that exact Windows workflow is tested.
